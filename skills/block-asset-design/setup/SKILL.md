# 准备资产工具脚本

配套脚本随整个技能集合安装。从当前安装的技能目录复制到目标项目，供后续任务按需修改和调用；无需另外下载 release 附件。

## 本地来源

[复制工具](scripts/copy_tools.py)根据自身位置读取集合内的脚本，生成独立的项目工具目录：

| 集合内来源 | 项目工具目录 |
| --- | --- |
| `shared/scripts/` | `checks/` |
| `texture/scripts/` | `texture/` |
| `review/scripts/` | `review/` |
| `mod-resource-extract/scripts/` | `resources/` |

各工具的依赖清单与适用声明一并复制，不包含第三方美术资源或游戏客户端适配器。保留完整技能集合的目录结构；来源缺失时报告安装不完整，不改从远端下载。

## 准备流程

1. 确认目标项目根目录，读取其工具目录约定。已有工具副本时复用其路径；首次准备默认使用项目内的 `tools/block-asset-design/`。
2. 已有副本且未要求升级时，保留全部本地文件并返回实际路径。旧 release 副本也可继续复用。来源未知时如实说明，不将其标为当前技能版本。
3. 首次准备时，审阅复制工具后运行下列命令，将示例路径替换为当前安装位置和实际项目路径。目标目录必须不存在，脚本不会覆盖已有目录。

   ```sh
   python3 /absolute/path/to/block-asset-design/setup/scripts/copy_tools.py --output /absolute/path/to/project/tools/block-asset-design
   ```

4. 明确要求升级时，先用同一命令复制到独立临时位置下尚不存在的目录，再与项目副本比较并合并，保留本地适配。无法判断的冲突保持现状并说明，不能重新复制覆盖项目目录。

## 完成

在对话中说明项目工具目录、当前技能来源路径（已知版本或提交时一并说明），并注明首次准备、复用还是升级。不能从安装路径推断版本。升级时说明是否完成、尚未解决的冲突及保留旧文件的影响；部分合并不能标为升级完成。

复制过程不执行资产工具、不运行场景检查；文件与布局检查仅确认工具已就位，助手仍须在使用时审阅、适配并验证相关脚本。
