# Blender 崩溃排查与插件生命周期

排查异常退出、失效引用，或实现插件注册、卸载和异步回调时，按相关章节检查。节点图截图和缩放问题见[界面时序](ui-timing.md)。

## 隔离试验

使用工程副本和独立配置目录验证有风险的操作，保留用户默认偏好和启动文件。设置 `BLENDER_USER_CONFIG`、`BLENDER_USER_SCRIPTS`、`BLENDER_USER_EXTENSIONS` 时，先创建目录，再在进程内确认实际生效路径。

启动失败时，先用最小命令确认能否进入脚本。根据失败阶段比较 GUI 与后台模式、配置或启动上下文，每次只改变一个条件，并记录对应命令和结果。已有失败证据后，调整试验条件再运行。

修改自定义 RNA 类型后，优先在新隔离进程验证。翻译字典等独立资源可单独重载；完整插件热重载使用可丢弃的工程实例测试。侧栏绘制、窗口上下文和交互仍需在 GUI 中验证。

## 注册与卸载

注册 Socket 等类型可能同步触发现有节点树的 `update()`。回调依赖的 RNA 尚未就绪时，用模块级生命周期状态阻止更新，在任何 `self` 属性访问之前返回。全部注册完成后才允许更新，开始卸载时先关闭更新；检查所有相关节点树和回调。

`self.bl_rna`、`hasattr(self, ...)` 和属性存在性检查也会访问 RNA，无法保护这种失效状态。原生段错误无法用 Python `try/except` 捕获。

注册期间的上下文可能受限。依赖场景或工程数据的初始化应等到上下文就绪；延后回调需支持取消，执行时重新确认目标仍存在。

卸载时先阻止新工作，停止自身任务并取消计时器、处理器和绘制回调，再按依赖顺序注销属性和类型。只清理本插件拥有的资源。支持热重载的插件，还需验证已有实例在禁用、重新启用后的实际更新和依赖功能。

## 失效引用

加载文件、撤销／重做、删除数据或切换会重建数据的模式后，重新获取所需 Blender 数据。异步回调通过项目已有的稳定身份定位目标；目标已失效时，结束本次操作。

## 失败判断

先区分 Python 异常、信号退出、脚本主动退出、卡住和画面未刷新，再确认失败发生在启动、注册、加载、运行还是退出阶段。

记录版本与构建、系统、启动参数、PID、退出码、最后完成的操作和输入副本身份。崩溃后立即将 `crash.txt` 与系统报告保存到项目诊断目录，使用唯一文件名，避免下次运行覆盖；保存前去除敏感参数。

结合 Python 栈、原生栈和触发操作判断原因。RNA 警告或系统报告中的等待线程名称，单独都不足以定位崩溃。缺少命令对应关系时，启动失败的原因应保留为未知。

结论说明原触发路径是否复测、覆盖哪些类型和场景。原路径通过才记为修复；换用其他路径后通过记为绕过，原问题继续保留。证据不足时说明还缺什么。

## 判断示例

以下案例整理自本地历史排查记录，未附原始日志；用于说明判断方法，不代表特定版本或其他工程已通过验证。

### 注册时访问 RNA

已有自定义节点实例时，重新注册 Socket 触发节点树 `update()`，随后在 RNA 属性访问处崩溃。加入 `self.bl_rna` 检查仍失败；改用模块级状态，在访问实例前返回后，当前节点树的重新启用和后续更新通过。另一种节点树仍出现同类问题，因此修复结论只能覆盖已经复测的类型。

### 翻译验证触发完整重载

测试翻译时，卸载并重新注册整个插件触发已有节点实例崩溃。只重载翻译字典后验证通过。这说明翻译可以单独验证，不能据此认定完整插件重载的问题已修复。

### 启动日志缺少对应命令

系统报告显示 Cocoa 应用初始化中止，但没有对应进程的启动命令。此时只能确定退出阶段，不能归因于后台模式、权限或具体系统组件。

### macOS 下加载前的 Metal 初始化崩溃

本地记录中，Blender 在受限执行环境内以 `--background --factory-startup` 启动时返回 139，尚未读取模型。崩溃栈包含 `supports_barycentric_whitelist`、`MTLBackend::metal_is_supported` 和 `GPU_backend_type_selection_detect`。启动输出中的 USD `ARCH_CACHE_LINE_SIZE` 警告本身不足以判定根因。

通过运行环境的授权机制，在正常系统环境中直接调用 Blender 应用内可执行文件，以相同后台参数和校验脚本重试后，检查通过，未保存模型。由于执行环境和启动入口同时改变，这只能作为绕过记录，尚未隔离两者的影响。

遇到类似情况，先确认失败发生在加载模型前，并核对崩溃栈是否指向 GPU 初始化，再对照启动入口和运行限制。需要更高执行权限时，使用工具提供的授权机制。不要仅因启动失败就修改模型或重装插件；已经进入模型求值、插件或脚本的崩溃，应按其实际调用栈调查。

可使用应用内可执行文件进行只读校验，路径以本机为准：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python <校验脚本>
```

后台模式不能单独排除 GPU 初始化问题；仍需检查实际退出位置。

官方参考：[Python API 崩溃排查](https://docs.blender.org/api/main/info_gotchas_crashes.html)。该链接跟随开发文档，使用前核查目标版本。
