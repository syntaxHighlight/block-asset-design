# 局部迭代

读取[工作约定](../shared/references/workflow.md)，确定当前可编辑源、目标、已认可要求、保护范围和已有证据。全流程调用时沿用传入的阶段目标；独立调用时，根据用户请求和资产补齐这些信息。只读审阅请求交给[审阅](../review/SKILL.md)，不启动修改循环。

针对本轮每项关键要求，确定需要观察的功能组、表面和状态，说明已有证据覆盖了什么、还需观察什么。先按[审阅](../review/SKILL.md)检查当前成果及部件之间的关系，再选择修复项；检查范围不能局限于已知问题。

## 制作与复查

选择最影响目标的一组相关问题，明确问题所在部位、出现条件和预期改善。按问题交给[建模](../model/SKILL.md)、[模型修饰](../refine/SKILL.md)、[贴图](../texture/SKILL.md)或[动画](../animate/SKILL.md)修改。这些技能完成一次制作后，回到本轮复查，不递归启动新的迭代流程。

修改后调用审阅判断实际效果，需要量化时再选择几何或 UV 检查。在原问题出现的条件或等效条件下复查，确认缺陷消除后才标为已解决；同时复查受影响的功能组、接口、材质或运动。

若原因来自共用的生成方法、映射或控制逻辑，还需检查授权范围内其他使用同一方法的部分。新发现的问题纳入本轮处理；超出授权范围时，说明影响并交由用户决定。

用当前资产的证据对比修改前后。缺少实际观察条件的部分标为未验证；脚本执行成功不能代替视觉或连续运动证据。

在对话中简要更新问题状态：待处理、已修改待复查、已复查解决，以及尚未验证的部分，并说明下一步的作用，无需生成逐轮报告。修改没有改善时，重新检查原因与方法，避免在相同方案间反复切换。仅撤回本轮造成的退步，保留用户、其他制作者及此前阶段的已有成果。

## 自主决定终点

结束前，按本轮要求审阅最后一次修改后的资产整体效果，逐项确认关键要求有相应观察支持、已发现缺陷已经复查解决。复用仍适用的已有证据，对受后续修改影响的部分补充验证。局部修复通过或本轮没有新增问题，都不能单独作为整体达标的依据。

满足用户目标及对应制作技能的完成条件、必要关联问题已处理、没有影响交付的已知缺陷时，可自主结束。无需等待用户逐轮认可，也无需穷尽主观上可能更好的版本；完成固定轮数或运行全部工具，都不能替代验收。

若缺少判断关键要求所需的证据，先在可用环境中补充验证。仍无法验证时，保留并交付当前成果，说明缺失条件和对验收的影响，标明尚待验证，不宣称达标，并暂停依赖该验证的后续阶段。非关键盲区不阻塞已完成工作的交付。

重复修改没有进展或约束相互冲突时，先判断剩余问题是否影响目标。只剩可选优化时，保留较好结果并交付；仍阻碍目标达成时，提供具体证据、已尝试的方法和需要决定的取舍，暂停依赖该决定的修改。不得通过降低已确认要求宣布完成。

用户设置时间或轮数上限时，遵守上限；达到上限后说明实际完成状态，不能因此视为达标。

结束时简述达标依据、未解决或未验证部分及当前源文件。全流程调用时返回这些结论，由全流程技能决定后续阶段；单项打磨不自行扩展为整体资产重做。
