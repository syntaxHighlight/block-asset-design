# 建模

先读[工作约定](../shared/references/workflow.md)；接手既有资产并继续修改时，再读[接手规则](../shared/references/takeover.md)。Minecraft 任务加载[Minecraft 制作规则](../shared/references/profiles/minecraft.md)。设计已确定、仅需改善拓扑、接缝或法线时，交给[模型修饰](../refine/SKILL.md)处理。

需要接口构件、既有模型或风格依据时按[资源查找与使用](../shared/references/resources.md)先查项目资产；指定模组的检查与提取交给[模组资源提取](../mod-resource-extract/SKILL.md)。

1. 确认用途、观看尺度、静态占位及所需接口。优先建立整体轮廓与主要分区，先解决空间冲突再细化；有机械功能时读取[机械设计规则](../shared/references/profiles/mechanical.md)，确认支承、连接和工作通路。
2. 分别表达功能组、运动组、材质分区和可能的合并范围，定义见[术语](../shared/references/glossary.md)。同步运动不代表可以合并；是否需要独立显隐、处理接触关系或供脚本单独使用，也影响对象能否合并。
3. 有运动需求时，用父子关系、原生约束和必要驱动器建立可预览控制，先验证关键姿态和空间。选择方法时使用[Blender 能力查询](../blender-capabilities/SKILL.md)。约束用于控制运动，几何是否碰撞仍需验证。时序、节奏、循环和任意帧跳转由[动画](../animate/SKILL.md)沿用同一套控制器完善；静态资产跳过此步。
4. 草稿可用构建脚本快速比较方案，说明重生成范围；用户手工修改过的区域先明确后续以脚本还是手工模型为准。进入模型修饰阶段的部分以当前可编辑模型为准，后续优先使用通用工具进行局部修改。
5. 用[审阅](../review/SKILL.md)观察整体、接口、支承和运动，并核对功能组内各部件的方向、连接和比例是否支持其用途；尺寸或造型网格对齐问题用[几何检查](../geometry-check/SKILL.md)。

完成条件：比例与构件关系符合本轮要求，所需接口有依据；有运动时，观察结果支持关键姿态在空间上可行的判断。源模型可继续编辑。草稿可以保留未细化的部分；整体设计方向尚未确定时，先调整比例与布局。
