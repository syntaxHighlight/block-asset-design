# 游戏内验收

沿用[工作约定](../shared/references/workflow.md)和本次授权，确定目标项目、待验资产与验收问题。适用于装饰方块、植物、物品、实体及机器等资产；按实际对象选择验收条件。单独验收不包含资产修复权限，已有修复授权可直接用于必要返修，无需逐轮人工批准。

本技能提供验收流程，不随安装提供通用游戏驱动。先读取目标项目的验证文档、构建任务、启动入口和校验器，核实它们当前支持的场景。制定操作和采样计划时，读取[项目适配契约与案例](references/project-adapter.md)，选择可用的客户端控制方式，并核对采集预算如何执行。需要新增或调整探针时，在授权的目标项目范围内实施和验证；缺少写入或启动权限时，完成其余检查并明确缺口。

## 确定本轮场景

从本次变化和已认可要求确定最小充分覆盖：相关放置方向与状态、物品显示上下文、材质透明性、光照、相机距离，以及受影响的交互或运动。只选与目标有关的维度；动态对象需要关键姿态和足以观察转换的连续片段，暂停姿态只能证明该时刻。

优先复用项目已有的准备、启动、观测、采集和校验入口。确认构建产物、资源包和依赖版本与待验修改对应；静态资源检查与服务端测试按项目规范运行，各自的结果只支撑其检查范围内的结论。

使用独立运行目录及可重建测试世界，限定场景搭建与配置变更范围，避免写入日常存档。需复制世界或临时改配置时，沿用项目的保存与恢复机制，保留已有改动。运行前确定本轮输出目录、场景标识、各阶段超时与退出条件。采集计划须给出分辨率、帧数、频率或时间窗口、单轮及含重试的总字节预算，并核对停止手段；具体方法见[采集预算与停止条件](references/project-adapter.md#采集预算与停止条件)。共享显示环境的客户端测试串行执行。

完成条件：每项验收问题都有对应场景、预期客户端状态和观察视角，且现有入口或获准适配能提供这些证据。

## 启动并确认客户端就绪

按项目入口构建和启动真实客户端，跟踪本轮进程、日志和运行目录。用项目就绪信号确认运行环境启动、进入目标世界、资源完成加载及模型烘焙；进程存在、启动命令返回或固定等待时间均不足以证明就绪。

搭建与交互优先走项目已有的真实服务端或游戏路径。命令已发送只表示发起操作，随后读取客户端实际同步状态：目标维度和位置、方块状态或实体、必要资源及相机；涉及界面或交互时再核对菜单、物品或阶段状态。需要暂停或固定随机行为时，通过项目支持的机制控制，并说明因此未覆盖的行为。

把控制过程拆成“观察状态、执行一步、等待可核对的结果”，逐步推进。探针可负责入世界、命令、相机和交互；需要验证按键、鼠标或菜单操作时，走对应的输入路径。直接设置测试状态只用于场景准备，不能证明被跳过的交互已经通过。控制方式与故障处理见[客户端控制方式](references/project-adapter.md#客户端控制方式)。

状态达到场景预期后，按项目稳定条件等待可渲染画面。动态采样使用客户端观测到的阶段或时间窗触发，保留样本顺序和间隔，避免用启动后的固定秒数猜测游戏进度。

完成条件：本轮客户端观察能证明进入了正确场景，并已达到每个待采样状态。

## 采集并校验本次证据

使用项目支持的游戏帧缓冲采集入口，例如在帧渲染完成回调中调用 Minecraft `Screenshot.grab`；接口和事件由目标游戏版本适配。以采集完成信号确认写入结束，保留原始输出与实际帧缓冲尺寸。桌面窗口图、离线渲染或旧截图不能代替本轮真实游戏帧。

连续帧、完整 trace 和纹理／几何转储默认关闭。需要时只采集明确的问题窗口；限制待写帧和日志增长，预算达到上限或证据已足够时停止新增采集。异步写入也须有超时和失败反馈。达到上限但证据不足时报告未完成，不自动延长窗口或开始无限重试；性能测量与有读回或重度追踪开销的诊断分开。

将场景、客户端观察、截图路径及采集时刻或序号关联到同一次运行。用构建产物或相关资源的可核对标识关联当前修改；记录必要的版本与运行配置。沿用项目已有记录格式，能够查明证据属于哪个输入、哪个状态、哪一帧即可。

把本次确定的输出目录显式交给项目校验器；若入口只支持查找最新目录，核验其确实属于本轮后再使用。检查失败标记、必需观察字段及场景覆盖，实际解码全部待验图像，核对完整性、尺寸和观察记录中的引用。构建成功、客户端自动关闭或退出码为零都不能单独表示验收通过。

完成条件：本轮所需样本齐全、可解码、状态断言通过，证据能追溯到当前输入；这只表示自动校验通过。

## 审阅实际画面并收敛

实际打开每张用于结论的原始图像，观察连续片段中与问题有关的转换。结合预期状态、视角与上下文，检查目标是否可辨、比例和朝向是否正确、纹理与透明面是否完整、接触与遮挡是否合理，以及交互或运动是否呈现预期效果。自动指标与视觉判断分别报告；PNG 合法、状态正确不等同于画面正确。

发现问题时，用本轮画面和观测定位到资源、场景条件或探针。已有修复授权时完成必要修复，重新构建受影响输入，复查相关场景；输入或配置变化后，旧画面仅作对照。无法从现有视角判断的项目标为未检查或无法判断，按需要补充有限采样。

任一阶段失败或超时，停止该轮并检查对应日志、失败标记和最后客户端状态。保留诊断所需的最少证据，明确失败发生在启动、同步、采集、自动校验还是视觉判断；修正原因后再作有界重试。只回收本轮拥有的进程与临时配置，不覆盖其他会话。环境缺失、权限不足或原因无法消除时，交付已完成部分及阻碍，并说明未验项。

交付时在对话中说明覆盖对象与状态、自动校验结果、实际画面判断、本轮证据位置及剩余限制。只有本轮要求均有对应证据且两类检查都通过，才给出该范围内的通过结论。用户或项目未要求时，不另建验收报告。

结束或重试前，按[证据保留与清理](references/project-adapter.md#证据保留与清理)保留结论引用的原图、必要观察和复现信息，检查引用后清理本任务已被替代的捕获。仍在写入或诊断需要的文件暂留；不因属于最终验收而长期保留整轮原始捕获。项目有捕获规则时一并遵循。
