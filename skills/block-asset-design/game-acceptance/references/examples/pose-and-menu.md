# 固定姿态与菜单同步

用于参考测试 API 驱动的资产验收。此示例已去除项目名、私有路径、类名和资产常量；步骤与结论是教学示例，不是某次运行报告。采集预算和停止方式遵循[项目适配契约](../project-adapter.md#采集预算与停止条件)。

## 任务

检查一个带活动部件的方块资产：不同朝向下的轮廓与贴图是否正确，指定工作姿态是否可辨，菜单显示是否与服务端同步。本例只检查准备好的姿态和菜单状态，不验收完整加工过程或鼠标操作。

## 操作步骤

1. 准备可重建的测试世界和独立输出目录，确认当前构建、资源及测试模组来自待验输入。记录允许的相机位置、姿态清单和本轮预算。
2. 启动真实客户端。测试模组在客户端回调中识别标题界面，通过游戏的世界加载入口打开测试世界，等客户端玩家与世界可用。
3. 将布景操作提交到集成服务端线程，通过测试 API 放置资产及必要参照物。按观察点和目标点确定玩家位置与朝向，再通过游戏 API 定位相机。
4. 调用资产的状态逻辑准备指定姿态，并使用测试环境支持的机制保持该状态。菜单通过项目菜单 API 打开。记录哪些自然推进或输入过程被跳过。
5. 客户端逐项核对方块状态、朝向、方块实体、模型加载和目标阶段；菜单样本还需核对实际界面及同步字段。满足条件后，按项目要求作有限稳定等待。
6. 检查剩余采集额度，在帧渲染完成后请求游戏帧缓冲截图，关联样本与客户端观察。等待明确的写入完成信号，再解码检查文件；超时或写入失败时停止该样本流程。
7. 对下一项姿态重复状态核对与有限采样。全部必需样本校验完成后逐张审阅原图，再退出本轮客户端并恢复临时配置。

每一步都有超时和失败出口。等待同步时可保留少量诊断样本，但诊断样本也计入预算，不因一直未就绪而持续截图。

## 记录什么

- 当前输入标识、样本对应的朝向和姿态，以及实际客户端观察。
- 实际相机、图像尺寸、截图序号或时刻、写入结果与图片路径。
- 未同步、模型缺失、写入失败或预算耗尽时的具体原因。

复用探针时，特别检查它是否只等待文件出现、忽略截图完成回调，或只靠固定样本数和总超时控制输出。这些做法不足以确认写入完成或限制总字节量；按目标项目补齐所需能力后再运行。

## 如何得出结论

如果姿态样本和菜单字段都符合预期，可报告“所列朝向与固定姿态的外观检查通过，菜单字段同步通过”。同时说明菜单由 API 打开，姿态经过测试准备。

不能据此报告“整段动画已连续播放”“所有鼠标交互已通过”或“自然加工时序正确”。若任务包含这些要求，应另走真实交互和连续观察路径。

结束时按[证据保留与清理](../project-adapter.md#证据保留与清理)逐文件保留结论引用的图片及观察，处理本轮不再需要的诊断捕获。
