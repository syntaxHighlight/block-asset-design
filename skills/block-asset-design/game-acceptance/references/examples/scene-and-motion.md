# 组合场景与短时运动

用于参考命令与客户端探针配合的验收。此示例已去除项目名、私有路径、类名和资产常量；步骤与结论是教学示例，不是某次运行报告。采集预算和停止方式遵循[项目适配契约](../project-adapter.md#采集预算与停止条件)。

## 任务

在同一测试场景中观察实体、透明装饰物、粒子及持有物，检查相机移动前后的遮挡和显示效果。只覆盖指定场景与运动窗口，不代表所有世界条件下都已通过。

## 操作步骤

1. 外部运行脚本准备独立游戏目录和可重建世界，确认构建及资源标识，保存需要恢复的临时配置，然后启动真实客户端。
2. 客户端界面状态机推进标题页、世界选择和加载。项目可通过界面 API 点击控件，但这只覆盖游戏内界面路径；需要验证系统焦点或键鼠输入时，另用对应输入层。
3. 入世界后，通过项目命令入口布置地形、实体和参照物，设置时间、天气、持有物及玩家位置。每批操作后读取客户端实际状态，确认区块和对象已经同步。
4. 由探针在 tick 中推进场景阶段和相机路线，记录客户端对象、相机及阶段状态。若探针固定热栏、释放按键或重设鼠标抓取，关闭同时争夺控制的桌面输入；需要人工接管时先停用相关自动控制。
5. 客户端进入已确认的阶段后，按计划采集静止关键帧、短移动序列和稳定后的关键帧。预设时间只能在对应阶段和就绪条件成立后使用，不能只按启动后的秒数盲采。
6. 每次采集前检查帧数、时间、字节及待写队列额度，关联实际样本时间和状态，等待写入完成。队列阻塞、暂停采样或丢帧造成的时间缺口均需记录；依赖完整窗口的结论不能忽略这些缺口。
7. 校验客户端观察、样本覆盖和图像解码结果，随后审阅原图及短序列。证据足够即停止；否则在剩余任务预算内处理问题，无法补齐时报告未完成。

固定样本数与客户端超时不能替代磁盘配额。源图形捕获、运行时序列或诊断转储若另有入口，分别核对其上限和停止方式，不默认随视觉验收全部开启。

## 记录什么

- 当前输入标识、场景阶段、实际可见对象及其客户端状态。
- 相机位置与朝向、每帧时间、实际尺寸、写入结果，以及计划与实际采样的差异。
- 使用的控制层、暂停或固定的游戏条件、预算消耗和停止原因。

性能测量单独运行，并按目标关闭截图读回与重度追踪。带诊断采集开销的帧时间只能用于说明对应测量条件。

## 如何得出结论

如果指定对象已同步、样本覆盖完整，且视觉审阅未发现问题，可报告“指定场景中，静止、移动和稳定后窗口的显示检查通过”，并列出覆盖的对象和条件。

界面 API 点击不能证明操作系统键鼠链路正常；固定相机路线不能证明任意视角都正确。恢复世界和配置也不表示捕获文件已清理，须另外按[证据保留与清理](../project-adapter.md#证据保留与清理)处理本轮输出。
