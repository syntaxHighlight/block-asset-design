# 项目适配契约与案例

规划客户端操作和采样预算、核实既有入口或补充探针时读取。本契约不规定公共命令、JSON schema 或游戏版本；具体接口以目标项目当前实现为准。

## 适配契约

先沿项目文档找到场景准备器、客户端启动任务、游戏内探针与结果校验器，检查输入、写入范围及真实断言。历史验收说明用于理解覆盖，执行参数和状态常量仍须与当前源码核对。

| 环节 | 项目入口应提供的能力 |
| --- | --- |
| 输入与隔离 | 确认当前构建和资源来源，限定测试世界、运行目录和临时配置，保存与恢复既有状态。 |
| 场景与就绪 | 通过真实游戏路径建立目标状态，区分启动、入世界、资源就绪、客户端同步及画面稳定，逐阶段有超时。 |
| 客户端观察 | 读取验收所需的实际客户端状态；仅记录发出的命令或服务端预期值不足以证明同步。 |
| 帧缓冲采集 | 在目标帧渲染完成后采集并等待文件写完；关联状态、尺寸、时序和路径，执行帧数、时间、字节及待写队列预算。 |
| 结果校验 | 对指定运行的必需观察、覆盖与原图解码做检查；失败、缺文件或超时明确暴露，不回退为读取旧成功结果。 |
| 结束与恢复 | 成功或失败均能结束本轮进程，恢复本轮配置；保留足以说明结果的证据，遵守项目保留与清理规则。 |

补齐缺项时，把实现放在获准修改的目标项目模块或工具目录，复用项目支持的游戏 API 和测试设施。将资产名、状态枚举、相机与采样计划保留为该项目的场景配置或断言；公共技能不携带某个资产的业务常量。

探针与正式产物按项目测试约定隔离，避免将临时场景或启动钩子混入发布包。新增代码运行与风险相称的最小验证，尤其检查失败传播、超时和证据关联。只读验收若缺少所需实现，先交付已有检查和适配缺口；技能存在不代表驱动已可用，也不授权修改项目。

## 客户端控制方式

先查明现有入口控制的是哪一层。以下方法可按场景组合，不能用其中一层的成功替代其他层的验证。

| 要做的事 | 可复用的控制方式 | 操作后核对 |
| --- | --- | --- |
| 启动、入世界、退出 | 外部脚本准备独立目录并启动客户端；测试模组的 tick 或界面状态机推进标题页、世界选择及加载 | 实际界面、世界与维度匹配，启动失败和加载超时可见 |
| 布置静态场景 | 服务端命令或测试 API 放置方块、召唤实体、调整时间天气和传送玩家 | 客户端已收到区块、实体和状态，资源已加载 |
| 调整视角与显示 | 探针设置玩家位置、朝向、视角模式和持有物，或使用游戏输入操作 | 实际相机、遮挡、物品显示上下文和 GUI 缩放符合计划 |
| 验证物品使用、菜单和加工流程 | 项目既有玩家交互或游戏网络路径 | 操作被接受，物品、菜单、阶段及服务端结果正确同步 |
| 验证键鼠行为或没有探针的界面 | 可用的桌面控制工具，或项目明确提供的键鼠输入驱动 | 窗口焦点正确，逐步观察结果，退出或失败时释放按键和鼠标 |

测试模组直接调用界面点击方法，与操作系统发送键鼠事件覆盖的路径不同；验证输入焦点或按键绑定时，应使用对应输入层。直接写入机器进度、物品或菜单状态可用于准备外观样本，但跳过了交互过程，不能据此宣布玩法通过。

采用逐步状态机：观察当前状态，执行一次操作，等待客户端出现预期结果，再进入下一步。等待条件使用实际的界面、区块、实体、菜单或阶段字段，并设超时；不要在结果未知时连续点击或重复发送非幂等命令。固定延时只可用于已确认状态后的有限稳定等待。

自动探针与桌面输入避免同时控制同一客户端。检查探针是否每 tick 重设相机、释放按键或控制鼠标抓取；这类探针可能覆盖人工或桌面自动化输入。需要接管时先停用相关控制，并保留恢复方法。桌面截图可用于识别界面和定位操作，资产验收图仍从游戏帧缓冲采集。

## 采集预算与停止条件

先列出验收问题需要的静态图和动态窗口，再决定数量。连续帧、完整 trace、纹理／几何转储默认不启用。每种启用的输出都需要范围和上限，不能用客户端运行超时或 JVM 堆大小代替磁盘配额。

计划至少包含以下值，写入项目已有运行配置或调用记录。这些是规划项，不是所有工具都支持的命令参数。

- 图像分辨率、关键帧清单，以及动态窗口的触发状态、采样频率、持续时间和最大帧数。
- 单文件、单轮输出和包含失败重试的总字节预算，以及启动前要求保留的磁盘余量。
- 待写图像的最大数量或内存预算、写入超时，以及日志和诊断转储的上限。
- 达到上限后的停止入口、当前轮次的结束方式和最少需保留的失败证据。

可从小计划开始估算，例如 8 张静态关键帧，加一个 3 秒、每秒 4 帧的动态窗口，共 20 张，整轮最多 24 张；示例分辨率为 1920×1080，单轮输出预算 256 MiB，含重试的总预算 512 MiB，最多 2 张待写图像。这些是可调整的规划示例，不是既有工具的默认值，也不表示足以覆盖所有动作。动作更长或需要更密采样时，重新分配预算；不能因达到示例帧数就认定验收完成。

按 `宽 × 高 × 每像素字节数 × 帧数` 估算原始图像量。1920×1080 的 RGBA8 缓冲每帧约 7.9 MiB，20 帧约 158 MiB；PNG 压缩比取决于画面，这个数不是 PNG 的固定大小，也不包含深度缓冲、复制缓冲和其他诊断文件。先用少量代表性样本核对实际体积，监测运行目录总增长，并为在途写入预留空间。

在发起读回或入队前检查剩余预算，避免先连续捕获再决定保存多少。队列已满时暂停采样或丢弃新帧，并记录错过的采样点和实际时间间隔。暂停采样时游戏可能仍在运行，因此暂停造成的时间缺口与丢帧同样处理：需要连续性证据的片段不能当作完整序列通过，重采须使用剩余总预算。达到帧数、时间、字节或磁盘余量限制中的任一项时，停止新增采集；等待已发起的写入在超时内结束，写入失败或超时标为未完成。日志可采用限量尾部或轮转，但保留失败原因、样本索引和必要状态。

区分软预算与硬上限。外部监控按间隔检查目录体积并停止本轮进程，可能在停止前继续增长；只有允许这种余量的软预算可使用小批次、保守余量和外部监控。先确认取消／终止路径，找不到可控停止方式时，不启动连续帧或大型转储。

要求硬上限时，在入队前为全部在途写入预占额度，并通过可执行的单文件限制或可靠大小上界核算；写入端限额或具备配额的输出存储负责阻止超额写入，超限须明确失败。PNG 的平均压缩率不能作为可靠上界。无法保证时报告能力缺口，不启动该采集，也不能退回外部监控后仍声称满足硬限。

重试计入同一任务总预算，不能换目录后从零计数。用写入计数或轮次记录累计生成量，清理或轮转文件不返还额度；当前磁盘占用另行监测，不能仅用目录现有大小计算剩余额度。证据已足够时提前停止。

性能测量单独运行，默认关闭截图读回、连续转储和重度追踪；需要开启时，在结果中说明测量条件。不要把带诊断采集开销的帧时间当作正常运行性能。

## 证据保留与清理

结束后先确定结论引用的样本，逐文件保留原始图像、对应观察、输入标识与必要的复现配置。动态结论需保留能支持它的短序列或片段；缩略图或拼图只能辅助浏览。将保留文件安置到项目约定的证据位置，更新引用并检查可读取性。

确认写入进程已经结束，再清理本任务归属明确、未被引用且不再用于诊断的连续帧、重复截图、trace 和资源转储。失败重试也按此处理：先保留最少诊断信息，再移除已被替代的捕获。仍被进程占用或仍需诊断的材料暂留，待条件解除后处理。不得借机清理其他任务、用户文件或长期测试输入，也无需另写逐文件删除日志。

测试世界、运行支持文件与捕获输出分开保存。供后续重跑的输入应有明确用途和生成方式，新测试不能隐式依赖某次历史捕获目录。
