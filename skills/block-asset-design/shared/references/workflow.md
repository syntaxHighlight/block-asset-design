# 工作约定

## 目标与自主程度

根据当前用户目标、已认可的参考与实际资产，确定本轮工作范围。日常细节与必要的关联修复默认自主完成。主体外形、机构方案、风格或接口方向的要求相互冲突，或方案与已认可要求冲突时，展示证据和选项。用户可指定偏自主或偏协商，该偏好在当前任务中持续有效。智能体的审美判断不扩大用户授权范围。

制作目标明确时，可自主推进至交付；偏协商时，更早提供小试样供对照，两种方式采用相同的质量标准。需要多轮打磨时，按[局部迭代](../../iterate/SKILL.md)完成制作、审阅与复查，并判断是否达到目标；跨阶段任务由[全流程](../../SKILL.md)安排后续步骤及需要返回的阶段。各阶段的制作技能遵守这些约定即可，无需因读取本文件重新启动全流程或局部迭代。

只读检查不包含修改授权。获得修复授权后，可自主组合检查与修复，无需逐项操作请求确认。用户目标达成、必要的关联问题处理完毕，才算完成；面数、岛数、固定轮数或运行所有工具都不能代替质量判断。

按当前问题选择主要使用的技能。需要跨领域局部修改时，读取相应规则；任务转为另一类独立问题时再切换技能，无需为每个局部操作切换。通过审阅判断效果、检查获取数据，并由制作技能完成修复。

## 文件位置

先确定本次任务的项目目录：优先使用用户指定的项目或当前工作区，结合已有模型和目录约定确认。技能安装目录及其所在仓库不代表目标项目；无法确定时询问保存位置，不凭脚本位置推断。

需要配套脚本时，先定位项目已有脚本副本；尚未准备时使用 [tool-setup](../../setup/SKILL.md)。调用项目内脚本，将脚本、项目输入和输出路径解析为绝对路径；配置文件内部的相对路径按对应工具的规则解析。

优先沿用项目已有目录，包括 `tools/machine-design/` 或 `assets/machines/`，无需为匹配技能名称搬动资产。没有约定时，可按需使用以下位置，不预建空目录：

| 文件 | 项目内建议位置 |
| --- | --- |
| 可按任务修改的配套脚本 | `tools/block-asset-design/` |
| 提取资源、原始声明和来源记录 | `assets/resources/<模组>/<版本>/` |
| 可编辑模型、贴图和配方 | `assets/models/<资产名>/` |
| 可重建的中间文件、预览和检查报告 | `build/block-asset-design/<资产名>/` |

提取结果写入新目录；已有结果先核验，符合要求便复用。临时目录只用于可丢弃的试验。交付前将需保留的文件放回项目，并更新依赖引用。项目文件不得依赖技能缓存或临时目录中的素材。完成后告知实际保存位置。

## 脚本适配

执行前按任务阅读项目内相关脚本入口及必要依赖，确认输入、写入范围和检查假设。优先使用已有参数；需要适配时修改项目副本，保留已有本地改动。资产的只读检查仍保持只读；脚本适配不扩大资产修改权限。

按改动风险做最小充分验证，实际任务中的调用也可用于验证，无需固定增加一次完整运行。检查算法发生变化时，用针对性样例核实结果；不得通过静默放宽阈值、跳过对象或隐藏失败来获得通过结论。报告影响结论的本地适配与未验证范围。

## 来源和恢复

草稿可参数化生成，说明重生成范围。进入模型修饰阶段的部分以当前可编辑模型为准；脚本多用于局部通用操作。仍需参数化调整的部件可以继续由脚本生成，但要与手工编辑区域分开。已有手工改动不能被旧构建器覆盖。

破坏性融合、应用修改器、删隐藏面或烘焙前，按实际需要保留可继续编辑的源数据或可可靠恢复的操作前状态。不默认复制整体资产、不累积版本目录。明确后续编辑哪份源文件，以及哪些输出需要随之重新生成。

保留继续制作所需的模型、配置和输入文件。公共工具不得依赖临时文件、过时的资产版本或个人电脑上的固定路径。需要更新项目文档时，遵循[记录规则](memory.md)。

## 检查结论

检查结论应区分四种情况：已检查且未发现问题、发现候选问题、未检查、无法判断。根据结论需要，说明对象、姿态、源/求值几何、UV 层、容差或覆盖范围，只报告影响结论及其适用范围的字段。旧证据可解释历史；当前结论应使用与当前资产对应的证据。局部通过不能外推为整体资产通过。

检查脚本只发现候选。空间网格对齐偏差、开放边、共享 UV、接触面不一定是缺陷；结合任务、例外和视觉判断决定修复。异常指标先检查检测假设，避免为满足不适用的指标而损坏模型。
