# Minecraft 制作规则

模型空间与纹理空间独立配置，不从 1/16 模型网格推导纹素密度。

## 模型

- 先确认目标 Minecraft 版本、加载器、资产用途和渲染/导出路径。普通方块、物品、多方块设备及自定义渲染器的几何与变换限制分别核实；不把某一种格式限制推广到其他格式。
- 确认模型单位、原点、朝向、显示变换和需要遵守的方块占位。接口遵循目标项目的连接面与安装基准，优先复用已核验资源。
- 造型网格和细节尺度由目标风格与观看距离确定；顶点吸附与形态冲突时，优先保持已认可形态。机械造型的可选细分网格、八边形与运动包络见[机械设计规则](mechanical.md)。
- 空间网格检查使用明确的原点、单位和坐标系。运动中的世界坐标不必逐帧吸附；参考态设计网格与运动轨迹分别判断。

## UV 与采样

- 尽量保持表面角度、长度比例及约定密度。必要时增加切口，不逐顶点强制取整。
- 规则面尽量让像素方向、边界与目标图像网格一致；斜面或曲面的像素对齐与保形要求冲突时，优先保形，并结合棋盘格和真实贴图判断映射是否合理。
- 源 UV 可用于编辑；最终生产 UV 必须在对应图集合法范围内，不依赖越界循环。图集内子区域还需单独检查范围；全图 0 到 1 检查不足以证明没有超出所属子图区域。
- 共享 UV 必须是有意共享，检查器报告后按用途确认，不能一律自动拆开。
- 像素预览使用最近邻，并检查原尺寸效果；留出扩边与间隔。运行时 mipmap 或透明排序未经验证时，明确说明。
- 接口原图保留方向、颜色、安装位置和适用语义。资源可用性见[资源约定](../resources.md)。
