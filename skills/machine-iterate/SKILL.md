# 局部迭代

读取[工作约定](../machine-design/shared/references/workflow.md)，确定当前可编辑源、目标、已认可要求、保护范围和已有证据。全流程调用时沿用传入的阶段目标；独立调用时从用户请求和资产补齐。只读审阅请求交给[审阅](../machine-review/SKILL.md)，不启动修改循环。

## 制作与复查

先查看当前成果，选择最影响目标的一组相关问题，明确预期改善。按问题由[建模](../machine-model/SKILL.md)、[模型修饰](../machine-refine/SKILL.md)、[贴图](../machine-texture/SKILL.md)或[动画](../machine-animate/SKILL.md)主导修改；这些技能完成一次制作后回到本轮复查，不递归启动新的迭代流程。

调用[审阅](../machine-review/SKILL.md)判断实际效果，需要量化时再选几何或 UV 检查。使用当前资产的证据，对比修改前后，复查受影响的接口、材质或运动；只在影响扩大时扩展检查。没有实际观察条件的部分标为未验证，不以脚本成功代替视觉或连续运动证据。

每轮保留足够的任务上下文：已解决什么、还剩什么、是否改善、下一步为何值得做；通常在对话中简述，不生成逐轮报告。无改善时重新检查原因与方法，避免在相同方案间反复摆动；仅撤回本轮造成的退步，保留用户和其他制作的已有成果。

## 自主决定终点

满足用户目标及对应制作技能的完成条件、必要关联问题已处理、没有影响交付的已知缺陷时，可自主结束。无需等待用户逐轮认可，也无需穷尽主观上可能更好的版本；固定轮数或工具全部运行不能替代验收。

若缺少判断关键要求所需的证据，先在可用环境中补验；仍无法验证时保留当前成果，说明缺失条件和对验收的影响，作为待验证交付，不宣称达标，暂停依赖该验证的后续阶段。无需为非关键盲区阻塞已完成的工作。

重复修改没有进展或约束相互冲突时，区分剩余问题：只剩可选优化就保留较好结果并交付；仍阻碍目标达成则提供具体证据、已尝试的方法和需要决定的取舍，暂停依赖该决定的修改。不得通过降低已确认要求宣布完成。用户设置时间或轮数上限时遵守上限，达到后说明实际完成状态，不视为自动达标。

结束时简述达标依据、未解决或未验证部分及当前源文件。全流程调用时返回这些结论，由编排决定后续阶段；单项打磨不自行扩展为整机重做。
