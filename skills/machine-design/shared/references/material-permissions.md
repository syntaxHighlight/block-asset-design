# 素材用途与授权确认

在复制、提取、裁切、改编或将第三方素材用于模型、贴图、预览及交付前，读取对应固定版本的许可证、署名要求及针对个别资源的例外条款。复用项目已有文件也适用；文件已在本地、目录标记可用或用户说“调用 IE 素材”，都不能代替用途确认。只读检索目录和协议可先完成。

## 何时询问

许可限制用途，而当前会话尚未明确确认满足条件时，必须先向用户说明具体限制和依据，再询问本次用途；等待答复后才执行依赖该用途的素材操作。询问应引用本文件与实际来源许可，说明为什么需要确认。等待期间可以继续目录筛选、协议核查及不依赖受限素材的工作。

例如用户要求调用 IE 原图，但没有说明项目是否属于 IE 附属模组：

> 这批 IE 素材的许可允许附属模组为附属用途使用和改编；独立素材包分发不在这项许可范围内。本次是否仅用于 IE 附属模组开发及相应成品交付，还是另有用途？

同时给出目录中对应版本的许可证链接。这里询问的是用途事实，不是让用户代替权利人授予许可。用户回答“可以”“继续”或“我承担风险”，但没有解决用途或授权缺口时，不能标记为已获许可。

当前会话已明确确认来源、用途和交付范围时不重复询问；项目文档、旧清单或归档只提供历史线索。用途从附属模组变为独立素材包、通用技能、其他项目或商业分发时，重新核对覆盖范围并确认变化。用户另外要求每次使用前确认时遵循该要求。

许可本身已覆盖明确用途、没有待确认条件的素材，保留必要声明即可，不为每次读取新增确认。仅观察风格与复制素材分别判断；观察需求不自动授权导入原图或生成含原素材的可分发预览。

## 如何判断与记录

分别核对本地观察、复制／修改、随成品交付、作为独立素材库再分发的依据；获准其中一种用途，不代表其他用途也获准。代码许可证不自动覆盖美术，免费发布和添加署名也不能补足缺失的许可。

将固定版本、许可原文及例外、本次用途、用户确认的范围或明确的另行授权证据，记录在项目已有来源记录或提取清单的 `permission_evidence` / `usage_scope` 中。只有用途确认和适用许可均已核实，才设置 `usage_status: confirmed`。工具校验这个字段不代表工具作出了法律判断。

没有覆盖用途的许可时，说明具体缺口并暂停该素材的复制、改编及交付，使用可用替代素材或等待权利人的适用授权；用户对任务的批准不扩张第三方权利。保留原始许可、署名和派生说明，不将第三方素材统一改标为技能或代码的许可证。

## 随技能发布

素材目录与来源映射可随技能发布；实际素材按逐项分发依据纳入，不能仅凭整库的“可用”状态。发布前核对原图、裁切图、模型、嵌入贴图的文件及预览是否均有覆盖此次公开分发的依据。

可分发素材需同时携带作者、固定来源、适用许可原文、所需署名、修改说明和文件哈希。未取得独立分发依据的来源只发布必要的目录与提取配置，实际文件留在获准用途的项目中。发布审核须检查真实文件清单；仅增加 NOTICE 或将文件移到 release 附件不会改变许可范围。
