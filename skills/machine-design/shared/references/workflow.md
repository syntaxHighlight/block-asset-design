# 工作约定

## 目标与自主程度

使用当前用户目标、已认可参考与实际资产确定本轮范围。默认采用适度自主的方式：日常细节与必要关联修复自主完成，主体外形、机构方案、风格或接口方向冲突时展示证据和选项。用户可指定偏自主或偏协商，该偏好在当前任务中持续有效。智能体的审美判断不扩大用户授权范围。

先定要判断的问题，再制作一批相关修改，集中审阅、定位缺陷并复查受影响部分。满足标准即结束；重复修改无进展或约束矛盾时回到设计取舍。偏自主允许多轮打磨，偏协商更早用小试样对照；两者共享质量标准。

只读检查不隐含修改。获修复授权后可自主组合检查与修复，不逐操作请求确认。完成条件是用户目标与必要关联问题处理到位，不以面数、岛数、固定轮数或运行所有工具代替质量判断。

技能边界规定主责，不禁止必要的跨领域局部修改。按当前问题选择主导技能，涉及其他领域时读取相应规则；只有任务转为另一类独立问题时才切换主导技能，无需为每个局部操作交接。审阅判断效果，检查提供数据，制作技能承担修复。

## 文件位置

先确定本次任务的项目目录：优先使用用户指定的项目或当前工作区，结合已有模型和目录约定确认。技能安装目录及其所在仓库不代表目标项目；无法确定时询问保存位置，不凭脚本位置推断。

技能目录只存放工具和说明。调用时使用脚本的实际安装路径，并将项目输入、输出路径解析为绝对路径传入；不要依赖启动命令时的工作目录。配置文件内部的相对路径按对应工具的规则解析。

优先沿用项目已有目录；没有约定时，可按需使用以下位置，不预建空目录：

| 文件 | 项目内建议位置 |
| --- | --- |
| 提取资源、原始声明和来源记录 | `assets/resources/<模组>/<版本>/` |
| 可编辑模型、贴图和配方 | `assets/machines/<机器名>/` |
| 可重建的中间文件、预览和检查报告 | `build/machine-design/<机器名>/` |

提取结果写入新目录，已有结果先核验复用。临时目录只用于可丢弃的试验；交付前将需保留的文件放回项目，更新依赖引用。项目文件不得依赖技能缓存或临时目录中的素材。完成后告知实际保存位置。

## 来源和恢复

草稿可参数化生成，说明重生成范围。进入模型修饰阶段的部分以当前可编辑模型为准；脚本多用于局部通用操作。仍需参数化调整的部件可以继续由脚本生成，但要与手工编辑区域分开。已有手工改动不能被旧构建器覆盖。

破坏性融合、应用修改器、删隐藏面或烘焙前，按实际需要保留可继续编辑的来源或可靠恢复节点。不默认复制整机、不累积版本目录。明确后续编辑哪份源文件，以及哪些输出需要随之重新生成。

保留继续制作所需的模型、配置和输入文件。公共工具不得依赖临时文件、过时的资产版本或个人电脑上的固定路径。记录按[memory.md](memory.md)执行。

## 检查结论

区分已检查未发现问题、发现候选、未检查、无法判断。按本次结论需要说明对象、姿态、源/求值几何、UV 层、容差或覆盖范围，只报告影响结论及其适用范围的字段。旧证据可解释历史，当前结论使用对应当前资产的证据；局部通过不外推为整机通过。

检查脚本只发现候选。空间网格对齐偏差、开放边、共享 UV、接触面不一定是缺陷；结合任务、例外和视觉判断决定修复。异常指标先检查检测假设，避免为满足不适用的指标而损坏模型。
