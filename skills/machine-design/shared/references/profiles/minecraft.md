# Minecraft 制作规则

模型空间与纹理空间独立配置，不从 1/16 模型网格推导纹素密度。

## 模型

- 多方块接口严格遵循目标包的方块网格、连接面与安装基准，优先使用已核验接口资源。不同接口形态遵循其自身契约，不能全部按整块立方体处理。
- 外形通常接近组成机器的方块占位，静态与运动包络分别确认。容差和是否允许突出由当前机器用途决定。
- 主体优先考虑 1/16 方块造型网格，部分细节可用 1/32，更细尺度需有表现或装配理由。形态优先于顶点吸附。
- 圆形通常以正八边形近似，截面内四边与网格方向平行。沿用已约定的半径定义（内切圆或外接圆）和取值步长；未约定时先明确，半径取该步长的整倍数。允许顶点偏离造型网格，不为对齐网格而改变八边形比例。
- 造型网格检查使用明确的方块原点、单位和坐标系。运动中的世界坐标不必逐帧吸附；参考态设计网格与运动轨迹分别判断。

## UV 与采样

- 尽量保持表面角度、长度比例及约定密度。必要时增加切口，不逐顶点强制取整。
- 规则面尽量让像素方向、边界与目标图像网格一致；斜面或曲面冲突时保形优先，结合棋盘格和真实贴图判断。
- 源 UV 可用于编辑；最终生产 UV 必须在对应图集合法范围内，不依赖越界循环。图集内子区域还需单独检查范围；全图 0–1 检查不足以证明没有超出所属子图区域。
- 共享 UV 必须是有意共享，检查器报告后按用途确认，不能一律自动拆开。
- 像素预览使用最近邻并看原尺寸；留出扩边与间隔，运行时 mipmap 或透明排序未经验证就明确说明。
- 接口原图保留方向、颜色、安装位置和适用语义。资源可用性见[资源约定](../resources.md)。
