# 模组资源检查与提取

根据用户指定的模组、版本、所需资源和使用方式开始工作；范围已明确时，直接检查。先查项目[已有资源与使用约定](../machine-design/shared/references/resources.md)，复用满足用途的结果，再检查缺口。已有索引可作为线索，协议结论仍须与目标版本和本次用途一致。

1. 从[素材目录](../machine-design/references/material-sources.md)或项目记录定位本地 JAR/ZIP 或官方源码版本，记录包哈希或提交号。区分观察参考、复制原图、裁切／改编、随项目分发及独立素材库发布。按[用途与授权确认](../machine-design/shared/references/material-permissions.md)处理用途限制：许可限制用途且本次用途尚未明确确认时，说明条款并询问用户，等待答复后再执行依赖该用途的操作；目录与协议调查可先完成。用户批准任务不能替代权利人的许可。
2. 读取该版本的 LICENSE、NOTICE、作者署名、资源专属声明和官方美术使用说明。代码和美术可能适用不同条款，逐项记录原文位置与对应用途。条款冲突或关键权限不明时，继续允许范围内的调查，说明具体缺口。提取或交付范围须有依据，不能用“开源”或脚本中的 confirmed 代替核查；只读查看和复制／改编的范围需分别判断。
3. 按[检查方法](references/inspection.md)从注册名、方块状态、模型和材质追查图像及父模型、子件、动画等依赖，比较候选资源的实际用途、像素尺寸、方向和配套关系。需要判断几何或材质时，预览代表性样本，不能只按文件名选图。

仅调查时，到此汇报候选、来源、适用用途、依赖和未解决限制即可；需要提取时继续以下步骤。

4. 形成最小提取清单，说明每项为什么需要、原样保留还是裁切、配套依赖及使用边界。按[清单与工具](references/manifest.md)填写来源、哈希和协议依据，随输出保留原协议与声明。包外的固定版本声明可作为独立文件纳入，并如实注明来自包外。
5. 使用项目工具副本中的提取脚本写入新目录；其他来源布局按同样契约保留来源和哈希。复核实际文件、图像尺寸／裁切方向、模型材质引用及声明是否齐全；模型与原 UV 有绑定时，一起验证。若仅提取局部参考，明确说明它不构成可直接导入的完整模型。

调查完成时，候选资源及其是否满足当前需要已有依据，依赖、用途和许可缺口已明确。

提取完成时，还需核实实际输出可追溯至固定来源，配套依赖完整，或已说明缺口及其对使用的影响，并随附协议及署名。将实际文件和用途补入项目已有资源索引，交付路径与必要说明。提取产物保存在目标项目中。
