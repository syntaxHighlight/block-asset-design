# 模组资源检查与提取

从用户指定的模组、版本、所需资源和使用方式进入；已有明确范围直接检查。先查项目[已有资源与使用约定](../machine-design/shared/references/resources.md)，复用满足用途的结果，再检查缺口。既有索引是线索，协议结论须与目标版本和本次用途一致。

1. **固定来源和用途。** 确定本地 JAR/ZIP 或官方源码版本，记录包哈希或提交号。区分观察参考、复制原图、裁切／改编、随项目分发；只澄清影响筛选或协议判断的缺失信息。
2. **检查适用协议。** 读取该版本的 LICENSE、NOTICE、作者署名、资源专属声明和官方美术使用说明。代码和美术可能适用不同条款，逐项记录原文位置与对应用途。条款冲突或关键权限不明时继续允许范围内的调查，报告具体缺口；提取或交付范围须有依据，不用“开源”或脚本中的 confirmed 代替核查。只读查看和复制／改编的范围分别判断。
3. **检查包内资源。** 按[检查方法](references/inspection.md)从注册名、方块状态、模型和材质追到图像及父模型、子件、动画等依赖；比较候选的实际用途、像素尺寸、方向和配套关系。需要几何或材质判断时预览代表性样本，不能只按文件名选图。
4. **形成最小提取清单。** 说明每项为什么需要、原样保留还是裁切、配套依赖及使用边界。按[清单与工具](references/manifest.md)填写来源、哈希和协议依据；原协议与声明随输出保留。包外的固定版本声明可作为独立文件纳入，不把它们伪称为包内文件。
5. **提取并验证。** 使用本技能的脚本写入新目录；其他来源布局按同样契约保留来源和哈希。复核实际文件、图像尺寸／裁切方向、模型材质引用及声明是否齐全；模型与原 UV 有绑定时一起验证。若仅提取局部参考，明确它不构成可直接导入的完整模型。

完成条件：选定资源满足当前需要，依赖完整或缺口已明确；输出可追溯至固定来源，协议及署名随附，本轮用途和未解决限制清楚。将结果接回项目已有资源索引，交付路径与必要说明；不把提取产物放入通用技能源码。
